# Architecture foundation

**Status:** accepted

## Scope

The project-wide Architecture decisions for VideoEditing: what is inside the
system and what it only uses, how it reads the transcriber, where each video's
files live, and where the agent instructions live. The components that do the
editing are settled with the `edit-video` feature; the internal design of the
scripts belongs to Implementation.

## Dependencies

- [Primary user](../product/product-foundation.md#primary-user) — the system
  runs only on this PC, driven by a coding agent opened in this repository, so
  the repository is the workspace.
- [Compatibility baseline](../product/product-foundation.md#compatibility-baseline)
  — original recordings are never modified, moved, or deleted, so the system
  only refers to them.
- [Data and privacy](../product/product-foundation.md#data-and-privacy) —
  nothing about a video, and not the reference photo, may go into git or to
  GitHub, so video folders and the channel folder are kept out of git; image
  generation may receive only what that rule lists.
- [Playbook](../product/product-foundation.md#playbook) — the user can change
  the playbook at any time, so it is kept as a plain file among the agent
  instructions.

## System boundary

Inside the system: the agent instructions, the scripts, and the video folders
in this repository.

Used but not owned: OBS, which produces the recordings; the local transcriber;
ffmpeg; the coding agent and its model provider; Codex and OpenAI's image
generation, for thumbnail images; Edge, which turns thumbnail layouts into
images; YouTube, where the user publishes by hand.

## Transcriber

The system uses the transcriber only through its launcher commands and the JSON
transcript they write, never through its Docker image or its intermediate
files. It uses it twice: to transcribe each recording that has no transcript
yet, and to transcribe each edit, or after a correction only the stretches of
it around the joins that changed, so that its joins can be checked. Transcripts
stay where the transcriber writes them, beside the recording or the edit.

Cut points come from the sentence segments that
[SebastianoTomasi/trascrittore#2](https://github.com/SebastianoTomasi/trascrittore/issues/2)
adds to that JSON. A transcript without segments stops the editing: the agent
says the transcriber must be updated, and works around it in no other way.

## Image generation

Thumbnail images are generated by Codex's built-in image generation, which
runs OpenAI's model on OpenAI's servers and saves the result on this PC. In
Codex the thumbnail skill uses it directly; in Claude Code the skill runs
`codex exec` with the `codex.exe` that the Codex app installs under
`%LOCALAPPDATA%\OpenAI\Codex\bin\`, which is not on the PATH. If it is
missing, the agent asks the user to run that step in Codex, and everything else
about the thumbnail is still made on this PC. What may be sent is fixed by
[Data and privacy](../product/product-foundation.md#data-and-privacy); text and
layout are never generated, they come from the channel template.

## Channel folder

The folder `canale/` in this repository holds what belongs to the channel
rather than to one video: the user's reference photo and the approved channel
template. Like the video folders, it is kept out of git.

## Video folders

Each video has a folder `videos/<YYYY-MM-DD>-<name>/` in this repository,
holding its video script, its cut list, its notes, its edit, and its
thumbnails. The folder is created by the first of these to exist: the video
script when there is one, otherwise the edit. Video folders are kept out of
git: nothing about a video is ever committed. Recordings stay where OBS writes
them, with their transcripts, and the folder refers to them by path.

## Agent instructions

The agent instructions are skills in `.agents/skills/`, linked from
`.claude/skills/`, so Claude Code and Codex read the same files. They live
only in this repository: nothing is installed in the user's global skill
folders. The
[playbook](../product/product-foundation.md#playbook) is a skill of its own,
`.agents/skills/playbook/`, which the other skills read and the user can edit
directly.
